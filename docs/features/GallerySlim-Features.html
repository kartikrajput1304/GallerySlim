1How GallerySlim keeps photos safe

GallerySlim frees storage in four ways: it shrinks photos and videos into smaller copies that are checked to look the same, it suggests clean-ups, it moves photos to a computer on the same Wi-Fi, and it keeps the phone slim with goals, overnight work and nudges. Every one of these is built on the guarantees below. A tester should treat any break of these guarantees as a severe defect.

The ladder of regret: every change is reversible first

1 · Smaller copyA new, checked copy is added to the gallery. The original is not touched.
2 · Ready to clearThe original waits. The user can Compare, or tap Keep original to throw the copy away.
3 · Android's trashOnly after the user confirms in Android's own dialog. Restorable for 30 days; Undo in the app.
4 · Delete for goodOnly on two paths, each with an in-app confirmation and then Android's own dialog.

The guarantees

GuaranteeWhat it means in practice
Nothing half-made is ever visibleA smaller copy is written hidden, decoded to prove it is readable, recorded in the app's queue, and only then made visible in the gallery. If any step fails, the hidden copy is removed and the original stays exactly as it was.
Every copy is checked before it is offeredPhotos must reach the preset's floor on SSIM, MS-SSIM and (for screen-like images) edge similarity, and then on SSIMULACRA2, measured against the original. Videos must pass a 5-frame spot check and a banding guard. Lossless re-optimisation keeps every pixel identical. A copy that fails is thrown away and the item is reported as skipped. Exception: Trim has no quality check (the result is a cut, not a look-alike); it still gets integrity checks.
Originals leave only through Android's trash dialogShrinking, overnight runs, trips, Make room and standing rules never trash or delete anything. They only make copies, queue originals in Ready to clear, or pre-select suggestions. The user always confirms in Android's own dialog.
Special photos are never silently degradedMotion photos are skipped by normal shrinking; their hidden clip is removed only through a separate consent dialog that offers to export the clips first. Ultra HDR photos only ever get a lossless re-optimisation that keeps pixels and the HDR gain map.
Protected by defaultFavourites and photos newer than the protect window (default 30 days; 7 or 90 selectable) start unticked; the user can still tick them by hand. Albums set to Never touch are excluded from every shrink path (manual, overnight, trip, Make room, light copy, trim). ID documents and photos the app could not read are never suggested for removal anywhere: Clean up lists, Duplicates, Quick review and Chat media (the "ID shield"). Photos not yet checked are shown as held and are never pre-selected.
Only two ways to delete for goodD1 — Free this space now: originals GallerySlim put in the trash, still in the trash, whose smaller copy is verifiably in the gallery and whose identity fingerprint still matches, re-checked one by one just before Android's delete dialog. Records made before this version (no fingerprint) are never eligible.
D2 — Send the trash to computer: items GallerySlim put in the trash, still in the trash, and verified by the GallerySlim Receiver in this sending run (the laptop re-read its saved copy from disk and its SHA-256 and size match the phone's file).
Both need an in-app confirmation and then Android's own dialog. Nothing else deletes permanently.
The original must be the same fileEvery clear, undo, keep and delete first re-checks the original's identity fingerprint (size, modified time and the media library's version). If the original changed since it was shrunk, nothing is done: the item moves to Can't be cleared safely — original changed in Ready to clear. Each of these operations is written down before Android's dialog opens and finished (or undone) when the app next starts or returns, so a crash never leaves it half-done.
GallerySlim only deletes its own copiesKeep original and Undo delete only the smaller copy GallerySlim made, and only after checking that the original is present (Keep original) or back in the gallery (Undo). Cancelling a contact sheet deletes the sheet image GallerySlim had just made.
30-day undoEverything GallerySlim trashed can be restored while it is in the trash (30 days): from Recent changes (Undo shown only while the original is still in the trash), from the Undo this run card, or from the phone's gallery trash. Items deleted for good (D1, D2) cannot be undone and show no Undo.
Honest numbersSpace in the trash is not counted as freed. All tools and Recent changes show "freed so far" and "still in the trash" separately, with the date the trash empties. (Your month counts cleared originals in the month they were confirmed, and says so on screen.)
Everything stays on the phoneNo account, no ads, no analytics, no uploads. Text reading, face and label detection run on the phone. The network is used only by Send to computer, over the local Wi-Fi, to a computer whose code the user scanned and confirmed. App data is excluded from Google backups and phone-to-phone transfers.
"Sent" is not "safe"A browser download only proves the bytes left the phone ("fully sent"); such files may be moved to the trash but never deleted for good. Only the Receiver's on-disk re-check makes a file "verified".
Optional safety vaultWhen the vault is on, an exact copy of each original is saved to a folder the user chose before it is shrunk. If that copy fails, the item is not shrunk.

2Reading this reference

2.1Conventions

  • Text in teal between quotes, such as Get space back, is shown in the app exactly like that. Highlighted italic parts such as Shrink N items are filled in at run time: N is a count (shown with thousands separators unless noted), size or X is a size, name a file name, d MMM a short date such as "24 Oct".
  • Paths are written Home›All tools›Big videos. "Home" is the minimal home screen shown after the first scan; "All tools" is the full dashboard behind it.
  • Each feature uses the same sub-headings: Purpose · Where · How it works · Rules & limits · What the user sees · Safety notes. "Docs vs code" boxes mark places where the design documents say something different; the reference always describes the code. "Tester note" boxes mark behaviour that looks unintended or needs a device check.
  • A snackbar is the one-line message at the bottom of the app. Android's trash dialog and Android's delete dialog are the system's own confirmation dialogs; items in the trash can be restored from the phone's gallery for 30 days.
  • The age of a photo or video is measured from its date taken, or its date added when the date taken is missing.
  • Only the Settings sheet is translated into Hindi; everything else is English (see Hindi).

3Getting started

3.1First launch and permissions

Purpose

Get access to photos and videos, then run the first scan. Nothing is changed at this stage.

Where

The app opens on the onboarding screen (no app bar) whenever it does not yet have media access. The same screen replaces Home and All tools until access is granted.

How it works

  1. The screen shows the title Your photos, just lighter and the body GallerySlim scans your gallery to show how much space you could reclaim — without deleting anything you haven't approved.
  2. A card lists three promises: Everything stays on your phone. No cloud, no account. · Smaller copies are checked before anything is replaced. Originals go to the 30-day trash only after you confirm. · You choose what to shrink or clean up, and can compare before and after.
  3. The button Allow access to photos opens Android's permission dialog. Caption: Android will ask you to confirm. You can change this anytime in Settings.
  4. When access is granted (fully or partly), the scan starts at once.

Rules & limits

Android 12Asks for storage read access (READ_EXTERNAL_STORAGE). Android 11 and older are not supported.
Android 14 "Select photos" (partial access)Treated as granted; the scan covers only the selected items. All tools then shows the row Showing selected items only — allow all for a full estimate; tapping it opens the app's system settings page. This row is not shown on the minimal Home.

What the user sees

The onboarding screen stays calm in every state (no red or error colours). After access, the scanning screen appears.

Safety notes

The app only reads media at this stage. The camera permission is not requested here; it is asked only when scanning a computer's code (Send to computer).

3.2Scanning (first scan and incremental re-scan)

Purpose

List every photo and video, detect special formats, and estimate how much space can be reclaimed.

Where

  • Runs automatically on every cold start of the app (when access exists) and right after access is granted.
  • Manually: Home›All tools›Rescan gallery (last row).
  • Also after an Undo of a clean-up or move row in Recent changes.
  • Not when the app returns from the background, and not on rotation. A second start while a scan runs is ignored.

How it works

  1. Reads all images and videos from the phone's media library: name, type, size, dates, favourite flag, album and date modified.
  2. For each JPEG it reads the first 128 KiB (and a Samsung trailer of up to 64 KiB) to detect motion photos and Ultra HDR photos. For each video it reads codec, resolution, frame rate, bitrate and duration.
  3. Each item is put in a savings category and given an estimate (table below).
  4. Items that already have a smaller copy waiting or confirmed are left out of the totals; items trashed through the app disappear from the totals at once, without a re-scan.

Rules & limits

Category (as shown)Which itemsEstimated saving
Camera photosJPEG, not a motion photo, not Ultra HDR35 % of size
Screenshots & imagesPNG60 % of size
VideosH.264 videos the shrinker expects to make smallerFrom the video bitrate plan; videos that are already lean count as 0; a flat 45 % if the video could not be measured
Hidden motion-photo videoMotion photos (checked first)The declared clip size, else 50 % of the file
HDR photosUltra HDR JPEG3 % (lossless only)
Already efficient or protectedHEIC, WebP, HEVC or AV1 video, compact H.264; Ultra HDR in a non-JPEG format; GIF, unreadable JPEGs, unknown codecs and other formats0
  • Motion photo: XMP MotionPhoto="1" or MicroVideo="1", or a Samsung trailer entry of type MotionPhoto_Data. A Samsung trailer without that entry is not a motion photo.
  • Ultra HDR: the JPEG's first 128 KiB contain an HDR gain-map marker (hdrgm:Version or ISO 21496).
  • A JPEG that cannot be read is classed as "other format" and is never shrunk (fails closed).
  • Incremental re-scan: results are cached on the phone. A cached entry is reused only when the file's size and modified time are both unchanged (and the modified time is known). New or changed files are read again; deleted files drop out. If the cache's version does not match, everything is read again.
  • The first scan (empty cache) keeps the scanning screen up for at least 1.5 s; later scans are not held. The screen updates at most every 100 ms.

What the user sees

  • A 160 dp progress ring: spinning until the total is known, then filling. Centre: the number scanned so far and of N.
  • Status line: Looking through your gallery… → Measuring photos… → Measuring videos…
  • Once the running estimate is above zero: Found size to free so far.
  • No cancel button. The screen stays on during the scan.

Safety notes

Scanning is read-only.

Docs vs codeThe UI spec lists a fourth status "Checking for hidden video…", category names "JPEG photos / PNG screenshots / H.264 videos" and a "Scanned 2 min ago" caption. The code has three statuses, the category names above, and no "scanned … ago" caption.

3.3Home (the minimal home screen)

Purpose

One ring, one sentence, one button: how full the phone is and how much can be got back.

Where

The start screen once the scan has finished.

How it works

  • Top bar: GallerySlim on the left; a tune icon (accessibility label Settings) on the right opens the Settings sheet.
  • Ring (240 dp): the filled part is the used share of the phone's storage (1 − free ÷ total). It animates over 900 ms (jumps straight there when Android animations are off). Centre: the free space as a number and unit (for example "12.3" "GB", or "850" "MB" below 1 GB) and the word free.
  • Under the ring: of total, followed by · almost full when the forecast is 0 days, or · full in about N days when the forecast is 1–365 days. Nothing is added when there is no forecast or it is more than 365 days.
  • Headline: You can get back about X when X > 0, otherwise Your gallery is already in good shape; both followed by without losing a single photo.
  • Button Get space back opens the guided flow. Caption: A few simple steps. You see everything before anything changes.
  • Ready-to-clear card (only when at least one smaller copy is waiting): size ready to clear / Smaller copies of N items are done. Tapping it asks for the app lock (if on), then opens Ready to clear.
  • Quick icons: Search → Search; Undo → Recent changes; All tools → All tools.

Rules & limits

  • X ("can get back") = the shrink estimate of all categories (including protected items and motion clips) + the savings of the copies waiting in Ready to clear + the size of confirmed originals still in the trash.
  • The ready-to-clear amount is the saving (original − copy), not the size of the originals.
  • Below 5 GB free (binary) the ring and number turn amber.
  • The forecast needs at least 3 free-space samples spanning at least 2 days within the last 30 days, and free space must be falling (see Widget and forecast).

What the user sees

As above. There is no other content on Home; everything else is under All tools.

Safety notes

Home only navigates; nothing here changes files.

Tester noteWhen nothing can be got back the headline reads "Your gallery is already in good shape" followed by "without losing a single photo." — the second line still shows.

Code: ui/HomeScreen.kt, ui/AppNavHost.kt, storage/StorageForecast.kt

4.9Photo quality checks and output

Purpose

The testable rules behind a photo copy: when it is accepted, what it looks like on disk, and what metadata it keeps.

Where

Applies to every photo shrink (manual, overnight, trip, Make room).

How it works

  1. Too compact for HEIC: a JPEG with estimated quality ≤ 65 and below 0.8 bits per pixel goes straight to the lossless path.
  2. Free space: needs at least 2 × the original's size + 300 MB free, otherwise skipped (space reason).
  3. Start quality: the preset's start quality, lowered by 15 if the source JPEG quality is below 70, or by 8 if below 85; kept within 40–95.
  4. Quality search: at most 6 encodes, step 8 (16 if the size did not change). A failed check steps quality up; a pass that is not small enough steps it down. It stops early when an encode is at least 1.5 × the original, or when the next step up — predicted as 1.84 × the last encode's size — could no longer save space (would exceed 90 % of the original), so that encode is not attempted.
  5. Check: the copy is scored at ≤ 512 px on the long edge. Score = the lowest of SSIM, 5-scale MS-SSIM and (for screen-like images, where at least 60 % of 8×8 blocks have 4 or fewer brightness levels) edge similarity; it must reach the preset's SSIM floor. Then SSIMULACRA2 must reach its floor (if it cannot be computed, the SSIM result decides).
  6. Accept the smallest passing encode that is at most 90 % of the original (saves at least 10 %).
  7. Lossless fallback (when HEIC fails or is hopeless, and for Ultra HDR): Huffman re-optimisation of baseline, single-scan, 8-bit JPEGs; pixels bit-identical; everything after the image (Ultra HDR gain map, Samsung trailer) copied byte for byte; kept only if it saves at least 1.5 %. Progressive, 12-bit, arithmetic-coded and multi-scan JPEGs are not supported.
  8. Publish: written hidden, decoded to prove it is readable, recorded, then made visible.

Rules & limits

PropertyHEIC copyLossless JPEG copy
File nameOriginal base name + .heic (e.g. IMG_1.jpg → IMG_1.heic)Same name as the original (the media library de-duplicates it)
FolderSame folder as the original when it is under DCIM or Pictures; otherwise Pictures/GallerySlim/album/
Date in the galleryDate taken copied from the original

4.10Video shrinking rules

Purpose

Turn H.264 videos into smaller HEVC videos that pass a visual spot check.

Where

Category Videos, Big videos (light copy), Get space back, Make room, overnight and trips.

How it works

  1. Plan a bitrate from the short side of the picture: ≤ 500 → 1.2 Mbps; ≤ 800 → 2.5 Mbps; ≤ 1200 → 5 Mbps; ≤ 1600 → 9 Mbps; ≤ 2400 → 16 Mbps; larger → 32 Mbps; × 1.5 at 48 fps or more.
  2. Skip with "Wouldn't get meaningfully smaller" if the planned bitrate is above 75 % of the source bitrate (would save under 25 %); otherwise use the lower of the plan and 55 % of the source. If both resolution and bitrate are unknown, skip.
  3. Content factor: the target is multiplied by 0.7–1.0 depending on how detailed 3 sample frames (at 25/50/75 %) are.
  4. Screen recordings (name starts with screen_recording, screenrecord or screen-, or album contains "screen record"/"screenrecord") above 32 fps are re-encoded at 30 fps.
  5. Free space: estimated output = (target bitrate + 256 kbps) × duration × 1.15; needs 2 × estimate + 300 MB free.
  6. Encode with the phone's hardware HEVC encoder (constant quality when available, else the planned bitrate). Audio is copied unchanged.
  7. Watchdog: if no progress for 120 s (checked every 5 s), the encode is cancelled ("stalled").
  8. Checks: output not empty; audio kept if the source had audio; duration within 1000 ms of the source; output smaller than the source; spot check of 5 frames at 10/30/50/70/90 % — every frame must score at least 0.90; banding guard — a frame fails if its banding index is at least 1.5 % and more than 1.0 point above the source's.

Rules & limits

  • Output name: base name.mp4 (HEVC in MP4); the media library may de-duplicate it to e.g. "name (1).mp4" (not verified on a device).
  • Folder: same as the original when under DCIM, Movies or Pictures; otherwise Movies/GallerySlim/album/. Date taken copied.
  • A video whose duration is unknown always fails the spot check.
  • Leftover work files older than 6 hours are cleaned up.
  • The output is always HEVC; AV1 encoding is not used.

What the user sees

Progress per item; reasons as listed in Skip and failure reasons. In Compare, the stored score is the lowest spot-check frame score.

Safety notes

A failed or stalled conversion leaves the original untouched and no copy visible.

Docs vs codeThe original design mentions VMAF and AV1 where hardware allows. The code uses the SSIM spot check plus banding guard, and never encodes AV1.

Code: shrink/video/HevcVideoShrinker.kt, BitratePlanner.kt, VideoQuality.kt, Banding.kt, SpaceBudget.kt

8.3Send to computer via the GallerySlim Receiver (gs2, phone side)

Purpose

Send to the Receiver program, which saves each file, re-reads it from its own disk and proves it matches; the phone then marks it verified.

Where

Same Send to computer screen; on the computer, open the Receiver (see GallerySlim Receiver).

How it works

  1. The Receiver finds the phone (it shows the phone's name and short code) and asks for a session, sending its computer name, system and folder name.
  2. Phone: scan the QR code shown by the Receiver (gs2:…). If it matches no waiting session: That code has expired. Restart the receiver on the computer and scan again. (no prompt).
  3. Prompt subtitle N files (size) to computer name → confirm → Sending to computer name. Each file is checked on the computer.
  4. For each file, the Receiver sends the SHA-256 and size of the copy it re-read from disk. The phone hashes the whole current file itself. If both match, the file is verified, saved immediately in the app's history (survives restarts), and counts as delivered. A mismatch is silently left out of the counts. A file deleted from the phone during the transfer is answered "gone" and the Receiver skips it ("No longer on the phone").

Rules & limits

  • The QR code is valid only while its session waits; at most 2 waiting sessions per computer address and 32 in total; sessions expire after 10 min idle.
  • Requests after pairing must be signed and come from the same IP: wrong IP → refused; expired session → "expired"; bad signature or replayed counter (already used, or 1024 or more below the highest seen) → refused.
  • All answers that carry a decision are signed; a file whose length changed since the list is answered "changed" and re-fetched by the Receiver.
  • Resume from a byte offset is supported; data is encrypted in 1 MB frames. The "at most 3 streams" limit is enforced by the Receiver.
  • Earlier verifications are matched by the same media id and size; they are labels only and never allow delete for good.

What the user sees

Step 4 when every delivered file is verified: N of M files (size) were checked on your computer and match exactly. Move them to the trash here. with Move N sent files to trash and the same dialog as the browser way. If browser and Receiver deliveries are mixed, the browser wording is used.

Safety notes

The pairing secret travels only through the camera, never over the network. "Verified" = the Receiver's on-disk re-hash equals the phone's whole-file SHA-256 and size.

Tester noteFiles the Receiver already had are verified without sending bytes, so the phone's progress bar may never reach "All … sent" even though everything is verified. The short code appears only in the Send screen hint, not in the confirmation prompt.
Docs vs codeThe Receiver plan's phone text "Verified on your Windows PC" does not exist; the phone says "…were checked on your computer and match exactly…", and the prompt names the computer's host name, not its system. The protocol says the short code is shown with the Receiver's name before the fingerprint prompt; it is not. The plan says the phone caches file hashes; the code hashes the whole file every time.

10.4Finding the phone

Purpose

Find the phone that is showing "Send to computer" on the same Wi-Fi, automatically or by typed address.

Where

The Finding phase; or --phone.

How it works

  1. One multicast name query for galleryslim.local; answers collected for 1.5 s; then the phone's ports 8765–8769 are tried at those addresses.
  2. If nothing answers: every address of each active IPv4 network with a /24 to /30 prefix is probed on 8765–8769 (300 ms timeout, 64 in parallel), excluding network, broadcast and the computer's own address.
  3. A phone counts only if it answers as GallerySlim protocol 2.

Rules & limits

  • Typed address: IPv4 with optional port, at most 64 characters (page: at most 100 before cleanup; http:// and paths are stripped). Host names such as galleryslim.local are rejected. Without a port, 8765–8769 are tried.
  • Page messages: Please type the address shown on the phone., That address is too long., That doesn't look like the phone's address. It looks like 192.168.1.23:8765.; no answer: no GallerySlim phone answered at addr; check that the phone shows "Send to computer" and is on the same Wi-Fi.
  • Networks wider than /24 (e.g. /16) are not probed: type the address.

What the user sees

The Finding phase texts above.

Safety notes

Discovery only reads the phone's public hello; nothing is sent until pairing is approved on the phone.

Docs vs codeREADME/protocol say "/24 or smaller"; the code also skips /31 and /32.

10.5Pairing, transfer, resume and verification

Purpose

Pair securely through the camera, download every file, and prove each saved file matches the phone's.

Where

Pairing and Receiving phases (page or terminal).

How it works

  1. The Receiver makes a 32-byte secret, shows it only inside the QR code (gs2:…) with the phone's short code, and polls the phone every 1 s (5 s timeout per poll).
  2. After the owner confirms on the phone, the file list is fetched (up to 3 tries, waits 1 s and 2 s).
  3. Free-space check: sizes of files not already present, minus partial downloads, plus a 50 MB margin. Short → error "not enough free space: need X, free Y" (the "need" figure excludes the margin).
  4. Sizes on the page and in the terminal use decimal units (1 kB = 1000 bytes) with one decimal below 10 and whole numbers from 10 up, e.g. "4.2 GB", "245 MB" (the terminal writes kilobytes as "kB"; below 1000 bytes it shows bytes).
  5. Up to 3 files download in parallel, encrypted. Each file is written as a partial file, moved into place without overwriting, re-read from disk and hashed, and the hash and size are sent to the phone, which answers "verified" or not.

Rules & limits

10.6Where files go and never-overwrite naming

Purpose

Save every photo into a month folder, with a name that works on every system, without ever overwriting an existing file.

Where

The chosen folder.

How it works

  • Layout: <folder>/yyyy-MM/name, or <folder>/undated/name when the month is unknown or malformed. Month folders sit directly inside the chosen folder.
  • The file's modification time is set to the date taken (unless it is ≤ 0 or more than 24 h in the future).
  • Hidden folder <folder>/.gallery-slim/: parts/ and manifest.json (a hint only; files are always re-checked).

Rules & limits

  • Never overwrite: tries name, name (2).ext … up to (9999); each name reserved with create-exclusive; on Windows and macOS names differing only in letter case count as taken; one lock per folder; file and folder synced to disk; renames briefly locked by antivirus or sync clients retried 6 times.

No existing file is ever replaced, including files from another phone with the same names.

10.7Keep-awake and idle auto-quit

Purpose

Where

Automatic.

Glossary

Album rule
A per-album setting: Default, "Light copy for photos older than N years" (1/2/3/5) or "Never touch".
All tools
The full dashboard behind the minimal Home screen.
Android's trash
The system's recycle bin for photos and videos. Items stay restorable for 30 days, then Android deletes them. Space is freed only when they leave the trash.
App lock
Optional fingerprint/PIN prompt before Ready to clear and the vault.
Banding guard
A video check that rejects copies showing visible colour steps ("banding") that the original does not have.
Burst
At least 3 photos in the same album taken at most 1.5 s apart.
Clean up list (lane)
One of the suggestion lists: Old screenshots, Old chat media, Low-quality photos, Expired, Old receipts & tickets, Greetings & forwards, Old downloads.
Contact sheet
One grid image showing every shot of a burst, saved before the extra shots go to the trash.
Cooling
The setting "Lighter copies of old photos": photos older than 1–3 years in Default albums become 2048 px light copies when shrunk.
D1, D2
The only two permanent-delete paths: D1 "Free this space now", D2 "Send the trash to computer" (Receiver-verified files only).
Fully sent
Browser (gs1) only: every byte of the file was written to the network. It does not prove the computer saved it.
gs1
The browser way of sending to a computer: a page served by the phone, a ZIP or single downloads; unencrypted on the local network.
gs2
The GallerySlim Receiver protocol: QR pairing, signed requests, encrypted transfer, on-disk verification.
HEIC / HEVC
Efficient photo (HEIC) and video (HEVC, H.265) formats that Android 12+ shows natively. GallerySlim's copies use them.
ID shield
On-device text reading that keeps identity documents and unreadable photos out of the Clean up lists.
Keep original
Rejects a smaller copy: GallerySlim deletes its own copy and leaves the original exactly as it was.
Keep until
A date after which an item appears in the Expired list; set by "Keep selected for" or by the expiry reader.
Keeper
The copy in a duplicate group that will be kept; chosen automatically, changeable by long-press.
Ladder of regret
The order of actions from most to least reversible: copy → Ready to clear → trash → delete for good.
Ledger
The app's count of confirmed shrink originals that are freed vs still in the trash.
Light copy
A preset (and Big videos action) that also reduces size: photos to 2048 px on the long edge, videos to 720 px on the short edge.
Lossless re-optimisation
Re-packing a JPEG's data more efficiently without changing a single pixel; used for Ultra HDR and as a fallback.
Make room
A plan to free a target amount, gentlest steps first.
Motion photo
A photo file with a short video clip hidden inside (Samsung, Pixel).
Never touch
An album rule that excludes the album from every shrink, light copy and trim.
Original
The photo or video as it was before GallerySlim made a smaller copy.
Preset
Gentle, Balanced, Aggressive or Light copy: the minimum quality a copy must reach.
Protect window
"Protect new photos for" 7/30/90 days: newer photos and favourites start unticked.
Quick review
One swipe queue over all suggestions and duplicate extras, ending in one trash dialog.
Ready to clear
The list of originals whose smaller copies are done and checked, waiting for the user to clear them to the trash.
Receiver
The GallerySlim Receiver laptop program (Windows, macOS, Linux).
Run
For Undo this run: the set of originals cleared in one Ready-to-clear dialog. For delete for good: one sending session since the queue was set.
Short code
Two letters and two digits (e.g. "K7-42") shown on the phone and by the Receiver, so the user can tell phones apart. It is not a password.
Smaller copy
The new file GallerySlim makes; labelled "GallerySlim" in Compare.
Snackbar
A short message at the bottom of the app screen.
Spot check
The video quality check: 5 frames, each must score at least 0.90.
SSIM, MS-SSIM, SSIMULACRA2
Measures of how similar two images look. GallerySlim requires every photo copy to reach the preset's floor on these.
Standing rules
The answers to the five questions: they pre-select suggestions, set the storage goal and cooling, and enable the weekly nudge.
Storage floor
"Keep this much space free": a goal that overnight shrinking and Make room work toward.
Trip mode
"Make room by a date": a one-off shrink the evening before a chosen date.
Ultra HDR
A JPEG with an extra HDR "gain map" layer (recent Pixel and Samsung phones). GallerySlim never re-encodes it.
Vault
Optional exact copies of originals in a user-chosen folder, made before shrinking.
Verified
gs2 only: the Receiver re-read its saved file from disk, and its SHA-256 and size equal the phone's whole current file.
